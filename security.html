Security & Defensive Systems Architecture

An overview of the defensive engineering controls, cryptographic standards, access controls, and data privacy safeguards implemented across this portfolio platform.

Cryptographic Authentication

Administrative access is guarded by cryptographic key derivation using modern primitives. No plaintext credentials are ever stored.

  • scrypt Key Derivation: Configured with N=16384, r=8, p=1 and 64-byte derived keys.
  • Cryptographic Salt: 128-bit cryptographically random salt generated per identity.
  • Constant-Time Verification: Comparison via timingSafeEqual prevents timing side-channel analysis.
  • Brute-Force Lockout: Automatic 15-minute IP lockout after 5 consecutive failed attempts.

Server-Side Authorization

Strict single-owner architecture. Public visitors operate in an isolated, read-only context with zero mutation authority.

  • Zero-Trust Client Checks: Client-side UI state is never trusted for authorization decisions.
  • 401 Unauthorized Barriers: Every administrative REST API enforces session validity on the server.
  • Cryptographic CSRF Tokens: State mutations require matching session-bound tokens.
  • Session Revocation: Sessions can be terminated individually or en masse with immediate effect.

Session Hardening

Owner sessions are maintained via hardened HTTP cookies isolated from client scripts.

  • HttpOnly Flag: Eliminates JavaScript access, mitigating Cross-Site Scripting (XSS) session theft.
  • SameSite=Strict: Strictly limits cookie transmission to same-site navigations, preventing CSRF.
  • 256-Bit Entropy: Session tokens generated with 32 bytes of cryptographic randomness.
  • Bounded TTL: Strict 24-hour session lifetime with automatic garbage collection.

Input Sanitization & Abuse Defense

All inbound data is validated against strict schemas before being accepted or processed.

  • Byte-Length Ceilings: Contact inquiries capped at bounded character lengths to prevent memory inflation.
  • Honeypot Traps: Automated bots completing invisible fields are silently dropped without persistence.
  • IP Rate Limiting: Public inquiry endpoints throttled to 5 requests per hour per IP.
  • HTML Escaping: All dynamic text rendered on clients is sanitized against injection attacks.

Binary File Upload Verification

Resume and document uploads are subjected to binary magic-byte inspection rather than trusting MIME headers.

  • Magic Byte Verification: File headers must start with binary %PDF- bytes.
  • Executable Rejection: Non-PDF or executable binaries (e.g. Windows PE, scripts) are rejected with HTTP 400.
  • 5MB File Size Cap: Protects against denial-of-service via memory exhaustion.
  • Immutable Destination: Saved strictly to fixed paths; user-controlled filenames are never trusted.

Data Privacy & Information Isolation

Defensive boundary isolation prevents unauthorized inspection of backend source code or private data.

  • Static Directory Barriers: Static file requests to .env, /data/*, or server source files return HTTP 403 Forbidden.
  • Sanitized Public Endpoints: Public data APIs strictly omit credentials, salts, hashes, and recruiter inquiries.
  • Privacy-Preserving Logs: IP addresses in recruiter messages are hashed with SHA-256 for abuse tracking.
  • No Third-Party Trackers: Zero ad networks, telemetry scripts, or external behavioral cookies.
